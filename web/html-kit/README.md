# Lemonade HTML kit — source

The source of the Lemonade HTML kit: plain HTML and CSS for prototyping Teya app screens, packaged as a
zip anyone can open and hand to an AI session. The screens look like the app because they use the same
tokens: colours, spacing, radii, type scale, Figtree and icons come from `web/styles/` and
`web/assets/`, which are generated from the same Figma exports as the KMP and SwiftUI code. Component
measurements follow the Compose components in `kmp/`, with SwiftUI as the tie-breaker.

## Build the kit

```sh
cd web
npm run html-kit
```

This writes `web/dist/lemonade-html-kit/` and `web/dist/lemonade-html-kit.zip`; pass `--out <dir>` to
write them elsewhere. It needs only Node, with no `npm install`. Share the zip. What the person who
receives it reads is `share/README.md`, which becomes the kit's `README.md`.

The skills and the plugin carry a version, `<major.minor>.<commits>`: major and minor from
`skills/plugin/plugin.json`, then the repository's commit count, so every commit is a new version. A build
with uncommitted kit changes ends in `-dev`; build from a clean tree for anything you share. Raise
major or minor in `plugin.json` by hand for a release that changes how the skill behaves. The skill names
its version when it hands over a screen or a review.

Open `web/dist/lemonade-html-kit/gallery.html` to see every component. The pages in this folder link
`lemonade-kit.css`, which exists only in the packaged kit, so opened from here they show a notice
instead.

## What's here

| Path | What it is | In the zip as |
| --- | --- | --- |
| `kit.css` | The components, as `lmnd-kit-*` classes, written against the `--lmnd-*` tokens | part of `lemonade-kit.css` |
| `build.mjs` | Generates `lemonade-kit.css` and packages the kit, the Claude.ai skill and the Claude Code plugin | — |
| `gallery.html` | Every component with its markup | `gallery.html` |
| `examples/` | Settings, Sales (with a filter sheet), Transaction details, Add recipient | `examples/` |
| `guidelines/` | The rules a prototype follows: Lemonade's `LDS-` rules in kit markup, and the kit's own `LHK-` rules | `guidelines/` |
| `SKILL.md` | Instructions for an AI session | `SKILL.md` |
| `share/README.md` | Instructions for the person who receives the kit | `README.md` |
| `share/build.mjs` | Makes a self-contained copy of one page; the tests use it to check pages | — |
| `share/build.py` | The same, in Python, for the Claude.ai sandbox | `scripts/build.py` in the `lemonade-prototype` skill |
| `skills/workflows/` | The design and review workflows, written once | each skill's `workflows/` |
| `skills/claude-ai/`, `skills/plugin/` | The entry `SKILL.md` of the Claude.ai skill and of each plugin skill, and the plugin's manifest and README | each package's entry files |
| `../llms.txt` | The package's token reference, generated by `scripts/web-llms-txt-converter.main.kts` | `llms.txt`, token sections only |
| — | Every icon, flag and logo name, generated by `build.mjs` | `assets.txt` |
| — | Every `lmnd-kit-` class, generated from `kit.css` by `build.mjs` | `classes.txt` |

`lemonade-kit.css` is the generated tokens and type scale, the package's own components (`lmnd-button`,
`lmnd-icon`, `lmnd-spinner` and the `lmnd-text-*` styles), `kit.css`, Figtree, and every icon, flag and
logo with one asset per line. The kit's components carry a `lmnd-kit-` prefix so they never collide with one
the package ships.

`tests/html-kit.test.ts` checks that `kit.css` names only tokens that exist and carries no colour of its
own, that every class a page uses has a rule, and that every page names only assets that exist.

## Changing the kit

- A new component goes in `kit.css`, with a demo in `gallery.html` and its rules, if it has any, in
  `guidelines/`.
- Measurements come from the Compose source in `kmp/`; where SwiftUI differs visibly, say which one the
  kit follows in a comment.
- Guideline files with an `LDS-` ID mirror the Lemonade guidelines and keep their IDs and meaning; only
  the examples are written in kit markup.
