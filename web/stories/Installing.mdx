# Installing

Lemonade for web ships as `@teya/lemonade-mobile-ds` — plain CSS custom properties, a
typography stylesheet, an icon mask utility, and framework-agnostic TypeScript
manifests. There is no React (or Vue, or Angular) runtime in the package: nothing
here requires a particular framework, which is why this whole gallery is a
documentation tool rather than a component library.

## Install

```bash
npm install @teya/lemonade-mobile-ds
```

## Import the stylesheets

Import once, at the root of your app.

```ts
import '@teya/lemonade-mobile-ds/tokens.css'
import '@teya/lemonade-mobile-ds/typography.css'
```

- **`tokens.css`** — every design token as a CSS custom property: spacing, radius,
  size, opacity, border-width, shadow, and the full semantic colour palette (light
  and dark).
- **`typography.css`** — the `.lmnd-text-*` classes shown in the
  [Typography](/docs/foundations-typography--docs) gallery.
- **`components.css`** — every component's classes: the `.lmnd-icon` mask, the spinner,
  the button. The React components import no CSS themselves, so this is not optional
  once you render one. The names are in the
  [Icons](/docs/foundations-icons--docs) gallery.
- **`fonts.css`** — the self-hosted Figtree `@font-face` declarations, if you want
  Lemonade to serve the typeface instead of loading it from Google Fonts yourself.
- **`styles.css`** — a convenience bundle that `@import`s `tokens.css`,
  `typography.css` and `components.css`. `fonts.css` is deliberately not included: it is build output, so
  the barrel would reference a file that does not exist in a source checkout. Import
  it alongside if you want the bundled typeface.
- **`lemonade.css`** — the same bundle, pre-flattened (no `@import`s), for pasting
  straight into a `<style>` block when your setup can't resolve package imports at
  all.

Every custom property is namespaced `--lmnd-*`, so it is safe to import alongside
another design system's tokens without a collision.

## Set the theme

Light is the default. Dark applies automatically from the OS colour scheme, or you
can force a theme explicitly by setting `data-lmnd-theme` on any element — typically
`<html>`:

```html
<html data-lmnd-theme="dark">
```

```ts
document.documentElement.setAttribute('data-lmnd-theme', 'dark')
```

This is exactly what the theme toggle in this Storybook's toolbar does — flip it on
any gallery page and watch every swatch, shadow and text sample re-resolve through
CSS with no JavaScript re-render required in your own app.

## Using tokens

For components styled in TypeScript, the root export carries the tokens as values.

```ts
import { tokens, tokenValues, textStyles } from '@teya/lemonade-mobile-ds'

tokens.color.content.primary   // 'var(--lmnd-color-content-primary)' — follows the theme
tokens.spacing[400]            // '1rem'
tokens.shadow.md               // the composed box-shadow
const title = { ...textStyles.bodyMediumSemiBold.style } // fontFamily, fontSize, lineHeight, fontWeight, …

tokenValues.spacing[400]                // 16
tokenValues.color.light.content.primary // 'rgba(9, 8, 6, 0.925)'
```

Style components with `tokens`: its colours are `var()` references into `tokens.css`, so they
re-resolve on the theme toggle above with no re-render. `tokenValues` holds plain numbers and
per-theme colours for code that needs a real value — a chart, a canvas, a `theme-color` meta
tag. A component styled with `tokenValues.color.light` stays light in dark mode.

## Icons, flags and brand logos

SVGs ship as static assets, plus a manifest of valid names so you get autocomplete
and can validate a name at build time:

```ts
import { iconNames } from '@teya/lemonade-mobile-ds'
// iconNames: readonly ["airplane", "appearance-dark-mode", ...] — 283 total
```

Render one with the `.lmnd-icon` mask class so it inherits `currentColor` and follows
the theme, the same way the [Icons](/docs/foundations-icons--docs) gallery does:

```html
<span class="lmnd-icon" style="--lmnd-icon: url('/node_modules/@teya/lemonade-mobile-ds/dist/assets/icons/airplane.svg')"></span>
```

In practice you'll usually resolve that URL through your bundler (e.g.
`new URL('@teya/lemonade-mobile-ds/icons/airplane.svg', import.meta.url)`) rather than a
hardcoded `node_modules` path.
